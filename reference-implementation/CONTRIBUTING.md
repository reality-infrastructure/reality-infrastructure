# CONTRIBUTING — Contract Discipline

## Two roles, never mixed
- **Research Claude** (chat): owns questions of necessity, prior art, theorems, spec revision.
  Almost never writes production code. Its outputs land in /research as immutable artifacts.
- **Claude Code** (this repo): owns implementation, tests, refactors, conformance. Treats SPEC.md
  as source of truth. Never revises the spec; surfaces conflicts via STOP CONDITIONS instead.

## The contract protocol (canonical: CONTRACT_TEMPLATE.md)
All work happens under a closed contract with this anatomy:
OBJECTIVE (one shippable end-state) · CONTEXT (exact files/lines only) · SCOPE (IN + explicitly
forbidden OUT) · PLAN GATE (plan before code; halt on unverified load-bearing assumptions) ·
CONSTRAINTS as MUST/NEVER one-per-line · deterministic ACCEPTANCE (tests/outputs) · fixed
VERIFY runbook · five-gate DONE report-back · STOP CONDITIONS.
Full form for shippable milestones; compressed form for intermediate fixes ending at "don't commit."

## Working rules
1. One contract at a time. The active contract is /contracts/CURRENT.md. Queue lives in /contracts/queue.
2. Fresh Claude Code session per contract. After compaction, re-read CURRENT.md + files it names.
3. Plan Gate is a real checkpoint: the plan is reviewed by Irvin before code runs.
4. Irvin does not hand-fix code. Fixes are delegated back via a new (usually compressed) contract.
5. Every milestone leaves the repository in a working state: tests green at every commit to main.
6. No-fabrication rule, adapted: no test may assert a value the spec does not determine;
   golden files are generated by the implementation, reviewed once, then frozen.
7. Completed contracts move to /contracts/completed/ with their five-gate DONE report appended —
   the repo's decision log.
